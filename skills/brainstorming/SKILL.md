# Brainstorming — 方案探索

对有影响的设计决策给出可检查的理由。遵循 [共享执行契约](../production-governance/references/workflow-contract.md)；探索方案不能覆盖已确认的用户选择或扩大授权。

## 使用时机

- 用户明确要求比较方案或选择技术方向。
- 现有项目约束仍无法确定的架构取舍，会改变可靠性、数据迁移、兼容性、维护成本或产品行为。
- 新证据推翻既有方案的重要假设，需要重新比较替代路径。

只存在两个可实现方法，不足以触发完整探索。既有模式已经覆盖需求、用户已指定方案、单值修正或清楚的缺陷修复，直接说明依据并推进。探索/修复策略中若实际出现重要设计分歧，也可使用本 skill，不能只按策略名称排除。

## 核心流程

### 1. 明确决策与约束

用一句话说明正在决定什么，列出用户目标、已有技术栈、不变量、现有授权和必须满足的验收。先查证关键事实；无法判断的产品需求由 requirement-clarifier 处理，未知技术事实优先调研。

### 2. 比较真实候选

通常选两到三个可行方案，数量由真实候选决定。若约束已经排除其他路线，可记录单一路径及排除理由，不制造陪衬方案。

每个候选说明：

- 核心做法与复用哪些现有能力。
- 对目标的覆盖、不满足或尚未确认的部分。
- 主要成本、风险、迁移/恢复方式。
- 适用条件，以及会让该方案不合适的具体条件。

选择表格或短段落，以便读者比较；不规定每项字数，也不以表格形式判断用户是否理解。

| 方案 | 主要做法     | 依据与收益         | 代价/不适用条件      |
| ---- | ------------ | ------------------ | -------------------- |
| A    | 复用现有组件 | 指向已读实现或实测 | 已知能力边界         |
| B    | 引入必要替代 | 指向需求与验证计划 | 迁移、依赖及维护成本 |

### 3. 推荐与证据补充

给出推荐方案和决定性理由，区分事实与假设。不用无来源的成本、性能数字或“最佳实践”代替当前项目证据。

取舍仍不明朗时，先确定是哪条未知事实影响推荐，通过小型探针、文档或代码检查解决。高复杂度且多视角确有价值时，再按 plan-ensemble 的授权与能力条件使用独立规划；不自动升级为多代理。

### 4. 决定并写回

- 用户已经选定：沿用该选择；新证据使它无法满足目标时，说明具体冲突和可行替代。
- 既有授权覆盖，属于必要可逆实现选择且证据充分：记录理由，直接进入实施。
- 关键产品取舍或授权范围仍无法确定：只就该缺口提问，不把所有方案变成必答审批题。

将结论、采用/放弃理由和剩余假设写入 RouteDecision.selection.notes 与 QuestMap.decisionNotes / alternatives。后续范围发现仍服务于已授权目标时，更新计划并自主继续；改变目标或引入未授权外部影响时才重新确认。

## 与相邻 skill 的关系

| Skill                 | 输出                                      |
| --------------------- | ----------------------------------------- |
| requirement-clarifier | 查证后仍缺失的关键需求答案或明确假设      |
| brainstorming         | 基于约束的候选比较、推荐与决定            |
| plan-ensemble         | 必要且获授权的独立视角草案与证据合成      |
| spec-driven           | 从选定行为和独立规则推导可执行 acceptance |

这些是按需能力，不是每个任务必须串行走完的流程。

## 反模式

- 已有明确技术约束却强制用户再次选框架。
- 为满足候选数量而列明显不可行方案。
- 候选无证据、推荐无理由，只让用户“你选吧”。
- 把自评分、代理投票或未经本任务验证的研究结论当作优越性证明。
- 未经说明改变用户选定的产品行为，或把必要可逆细节也升级为审批。

## 验收场景

- 用户要求“沿用项目现有 session 加登录”：复用已知方案并验证，不强制再选 OAuth/JWT。
- 用户要求迁移数据库并比较停机方案：展示真实迁移/恢复约束及推荐；只有业务停机容忍度缺失时澄清。
- 两种纯内部函数拆法均满足需求：依据现有风格选最小改动，不启动多方案会议。
- 数据规模探针推翻缓存假设：重新比较受影响方案并更新验收，不因已写计划而继续错误路径。
