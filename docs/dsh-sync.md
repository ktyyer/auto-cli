# Auto-DSH 超级编码同步维护

本机的 **Auto-DSH 超级编码** 来源于 Auto CLI，并保留 DSH 的工具、状态接口和本地扩展。用户已要求后续持续同步。每次完成本仓库的优化、升级、重新打包或安装时，都要核对并更新这一预设；不能只更新 Codex 和 Claude 后结束交付。

这是随本仓库维护执行的同步流程。没有安装后台更新器或定时任务。

## 来源与位置

| 对象         | 本机路径                                                                                   | 职责                                       |
| ------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------ |
| Auto CLI     | `D:/dev/auto-cli`                                                                          | 共享指令、协议、验证和观测工具的上游       |
| DSH 适配源码 | `D:/dev/auto-dsh`                                                                          | 维护 DSH 原生入口、工具映射及同步清单      |
| 已安装预设   | `C:/Users/kashe/.dsh/.agent-presets/auto-dsh`                                              | DSH 实际发现的用户预设                     |
| 桌面版 CLI   | `C:/Users/kashe/AppData/Local/Programs/DeepSeek Harness/resources/runtime/cli/bin/dsh.cmd` | 核验当前实际宿主位置的线索；升级后重新确认 |

两个 DSH 目录是独立目录。先分别检查现状和本地修改，不能假定源码目录始终更新。此次检查发现已安装目录比源码目录多出本地扩展，因此同步必须保留两边有效改动。

预设内的 `SYNC.md` 记录适配边界与维护命令，`sync-manifest.json` 记录共享文件和适配来源的实际哈希。本文件负责让 Codex 和 Claude 在后续维护时都能找到该流程。

## 每次更新的步骤

1. **固定输入。** 完成 Auto CLI 的适用检查，记录版本、Git 基线、未提交改动及实际源文件哈希。版本号相同也可能有不同本地构建。检查两个 DSH 目录的 Git 状态、文件清单和实际加载器路径。
2. **备份并暂存。** 把拟修改的源码、已安装文件和清单分别快照到本次 `.auto/runs/<runId>/dsh-sync/`，记录哈希。以实际较新的内容为依据合并，不覆盖用户已有修改。
3. **同步共享文件。** 按预设的同步清单复制共享协议、指标、反馈、验收和观测工具及其完整依赖闭包。所有直接共享的文件必须与上游逐字节一致，同时保留许可证。新增导入或读取依赖时，更新清单并实际检查；只复制入口脚本不够。
4. **适配指令。** 对照上游变化更新 DSH 的入口、技能和验收规则。保留 DSH 的工具名、任务状态接口、路由器，以及 `j-space`、`newapi-guardian`、`codegraph-intelligence` 等本地扩展。不能把 Claude hooks、Codex 专用路径或不具备的宿主能力原样带入 DSH。
5. **验证暂存结果。** 用 `check-sync.js` 核对来源哈希、共享字节和依赖；用 `validate.js` 加载本机真实 DSH 的配置 schema、注册结构和技能提供器。命令以预设 `SYNC.md` 的已验证用法为准。静态或离线加载通过不能写成真实模型任务收益。
6. **更新两个目录。** 验证通过后，重新核对拟覆盖文件仍与备份一致，再应用到适配源码和已安装预设。逐项核验实际文件、清单、技能发现及本地扩展，保留备份与执行输出。无需为例行同步重复询问已授权的选择；发现新的用户改动则先按来源合并。
7. **收口记录。** 在 run 中记录上游哈希、两个目标位置、同步清单、保留项、实际验证命令/结果和恢复材料。若本次上游变化不涉及预设，记录对照依据及“无需变更”。缺少本机 DSH 时记录未同步及原因，不能宣称三端同步完成。

同步检查命令（源码与已安装预设分别执行）：

```powershell
node D:/dev/auto-dsh/scripts/check-sync.js --auto-cli-root D:/dev/auto-cli
node C:/Users/kashe/.dsh/.agent-presets/auto-dsh/scripts/check-sync.js --auto-cli-root D:/dev/auto-cli
```

`check-sync.js` 只检查并报告差异，不会替代人工适配或自动覆盖文件。实际 DSH 更新是否需要重载应依据当前宿主行为；不要擅自终止用户的会话或重启其他服务。凭据和无关通信配置不属于同步输入。
